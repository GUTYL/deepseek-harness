# 第 1 章 · 为什么要学 TypeScript,以及这个项目是什么

## 本节要学的概念

- 什么是「类型」,静态类型(type checking)和动态类型(dynamic typing)的区别。
- TypeScript(TS)和 JavaScript(JS)是什么关系。
- 我们要用来当教材的这个项目,到底是个什么东西。

## 从一个问题开始

想象你写了一段 JavaScript:

```js
function greet(person) {
  return "Hello, " + person.name
}

greet("DeepSeek")
```

这段代码能跑吗?能。但运行结果是什么?`"Hello, undefined"` —— 因为字符串(在这段 JS 里)没有 `.name` 属性,你得到一个 `undefined`,程序照样往下走,没有报错。

直到很久以后,某个地方用到了这个 `undefined` 结果,你才会在十万八千里外看到一个奇怪的错误。**JavaScript 的运行期(runtime)不帮你检查「你传的东西对不对」,它只在你真正撞上错误的那一刻才崩溃。**

这类「本该早点暴露、却拖到很晚才暴露」的错误,正是 TypeScript 要解决的问题。

## 类型是什么

**类型(type)是对「一个值长什么样」的描述。**

- `"DeepSeek"` 是一个 **字符串(string)** —— 一串文字。
- `42` 是一个 **数字(number)**。
- `{ name: "DeepSeek" }` 是一个**对象(object)**,它有一个叫 `name` 的字段。

**动态类型**的语言(比如 JS):这些「一个值是什么类型」的信息,只存在于程序运行期间。你写代码时,编译器并不检查。

**静态类型**的语言(比如 TS):你在写代码时,就**给代码标注类型**,编译器在**你保存代码、还没运行之前**,就检查「类型对不对」。上面的 `greet("DeepSeek")` 会在你写代码时就被标红:字符串没有 `name` 属性。

一句话总结:

> TypeScript 不是一门全新的语言,而是「加了类型批注(和类型检查)的 JavaScript」。

## TS 和 JS 是什么关系

这是新手最常有的疑问,值得单独讲清楚:

1. **TS 是 JS 的超集(superset)**:所有合法 JS 都是合法 TS。你会 JS,就自动会写 TS 的一半。
2. **浏览器和 Node 只认识 JS,不认识 TS**:所以 TS 代码最终会被一个叫 `tsc`(TypeScript Compiler)的工具「翻译」成 JS 再运行。这个过程叫**编译(compile)**。
3. **类型在编译后消失**:类型标注只是给编译器看的,运行时不产生任何代码、不花任何运行成本。这个特性后面几章会反复用到,先记住:`type 只存在于编译期,运行时就没了`。

这张图帮你建立心智模型:

```text
你写的 TS 源码(带类型标注)
        │
        │  tsc 编译 + 类型检查
        ▼
纯 JS(类型已擦除)
        │
        │  Node / 浏览器 运行
        ▼
程序的运行结果
```

## 这个项目是什么

现在,把我们接下来 26 章的「教材」介绍一遍。

本项目叫 **DeepSeek Harness**(缩写 `dsh`),是一个[开源的智能体(agent)运行框架](https://github.com/deepseek-ai/deepseek-harness)。「智能体」的意思是:给它一个任务,它能自己调用工具——跑命令、读写文件、上网搜索、派生子智能体——一步步把任务做完。

你不需要现在理解它怎么实现,只需要记住它最核心的一句设计哲学,它会贯穿我们全部内容:

> **一切皆插件(Everything is a plugin)。**

连「调用大模型」这件事本身、连「智能体的主循环」本身,都是插件。这意味着项目的每一个部分都可以被配置替换。

这个项目为什么特别适合学 TypeScript?三个理由:

1. **它是真实生产代码,不是教学玩具**:里面用到的 TS 特性,都是「解决真实问题」才用上的,不是炫技。你会看到每个语法为什么存在。
2. **类型系统压得很满**:打开 `tsconfig.base.json`,你会看到 `strict`、`noUncheckedIndexedAccess`、`exactOptionalPropertyTypes` 这些「最高档」的严格开关全都开了。这意味着项目会把 TS 类型系统用到很深的程度——天然是「由浅入深」的好教材。
3. **规模刚好**:它由几十个包(package)组成,每个包职责清晰(见 [`packages/README.md`](../../packages/README.md)),你可以一次读懂一小块,逐步拼出全貌。

## 你现在能自己读了

既然还没学语法,这一节我们先「看形状」。打开 [`architecture.md`](../architecture.md)(这是整个项目的架构地图),不求看懂,只感受一下它的组织方式:

- 它有「Core packages」一节,用一张表列出每个包「拥有什么」。
- 它有「Turn flow」一节,用一段文字描述智能体一次任务的执行流程。
- 它有「Where new behavior goes」一张表,回答「我想加个 X 功能,该往哪挂」。

你现在读不懂细节很正常。我们的目标是:26 章之后,这张表里的每一个词,你都能讲清楚它在代码里对应什么。

## 小结

- **类型**是对值的形状的描述;静态类型在运行前检查,动态类型到运行才暴露问题。
- **TS = JS + 类型标注**,类型只存在于编译期,运行前就被擦除。
- 我们的教材是一个「一切皆插件」的智能体框架,类型系统用到很深,是天然的进阶教材。

## 思考题

1. 用自己的话说说:为什么 `greet("DeepSeek")` 在 JS 里「能跑但结果错」,而在 TS 里「根本跑不起来」?
2. 「类型在编译后消失」这句话,和「类型不会拖慢程序运行」有什么因果关系?
3. 打开 [`architecture.md`](../architecture.md) 的「Core packages」表格,挑一个你听起来最陌生的包名,记下来——读到后面某一章时,你会突然懂它是什么。
